# Rhine Visual System & Asset Hierarchy Specification
# 莱茵生命渲染器视觉系统与资产回退规范

本文档正式定义 `arknightsclip` 中 Rhine Renderer 的视觉层级、素材回退链、安全画幅规范以及与 Pen 设计工程的分工边界。

---

## 1. 核心定位与架构分工 (Architecture & Roles)

| 模块 | 定位 | 角色与权责 | 变动约束 |
|---|---|---|---|
| **Rhine Renderer** (`renderers/rhine/`) | **主执行视频渲染链路 (Primary Pipeline)** | 负责全量 1920x1080 @ 24fps 确定性帧渲染、动态转场动势、响应式玩家槽位矩阵与最终视频交付。 | 唯一主维护渲染实现，解耦自所有旧 Pen 坐标。 |
| **Pen Design System** (`psd2pen/`, `.pen`) | **设计参考与辅助资产 (Design Reference & Lab)** | 负责离线 UI 视觉原型、组件探索与参考标定。 | **严格只读审计**，绝不直接二进制覆盖损坏；依赖通过 portable manifest 显式映射。 |
| **Data & Asset Facts** (`data/`, `cards_raw/`) | **唯一事实源 (Single Source of Truth)** | `five_players.json`、`data/manifests/`、原始卡片切片与立绘。 | **不可破坏**，严禁私自篡改、重命名或静默覆盖。 |

## 2. 视觉资产层级与回退链 (Asset Hierarchy & Fallback Policy)

Rhine 视频管线遵循严格的**显式三级递降回退机制**，杜绝任何静默贴图替换（Silent Wrong-Image Substitution）与空白崩溃：

```
[干员数据激活 (Operator Scene)]
           │
           ▼
   ┌──────────────────────┐
   │ 1. Hero Art 立绘检测 │ ──(存在 full.png)───► [MODE A: hero_art]
   └──────────────────────┘                     - 居中宏大标本舱 (840x740)
           │ (缺失)                             - 响应式玩家底栏徽章
           ▼
   ┌──────────────────────┐
   │ 2. Card Art 切片检测 │ ──(存在 raw/cache)──► [MODE B: card_art]
   └──────────────────────┘                     - 左侧卡片标本舱 (500x740)
           │ (缺失)                             - 右侧五玩家获取矩阵 Dossier (580x740)
           ▼
   ┌──────────────────────┐
   │ 3. 结构化元数据兜底  │ ────────────────────► [MODE C: metadata_only]
   └──────────────────────┘                     - 全屏工程遥测档案板
           │ (格式非法/数据损坏)
           ▼
   ┌──────────────────────┐
   │ 4. 显式报错中断机制  │ ────────────────────► [FAIL LOUDLY]
   └──────────────────────┘                     - Canvas 渲染深红错误诊断横幅
                                                - __RHINE_RENDER_READY__ = false
                                                - 脚本抛出异常退出，严禁输出黑屏帧
```

### 层级规范：
1. **Mode A (`hero_art`)**：
   - 目标：拥有官方立绘（`assets/operators/{char_id}/full.png`）的干员。
   - 展现：大型中央标本舱（840x740），技术边角线，动态全息扫描线，底部水平响应式玩家槽位。
2. **Mode B (`card_art`)**：
   - 目标：未录入全立绘但拥有游戏卡片切片（`cards_raw` / `generated/cache/cards/`）的干员。
   - 展现：左侧卡片标本镜框（500x740），右侧并列 Rhine 技术档案遥测板（580x740）与垂直玩家矩阵。
3. **Mode C (`metadata_only`)**：
   - 目标：立绘与卡片均未就绪的极端情况。
   - 展现：极简高对比度深色遥测板，明确标明 `RECORD ACTIVE (METADATA ONLY)`，保留完整玩家练度事实。
4. **失败告警 (Fail Loudly)**：
   - 契约缺失、网络中断或数据结构不符时，严禁静默退回到默认图（如默认全天使或空白）。
   - 立即在画布绘制 `#4a0e0e` 错误横幅并设置 `window.__RHINE_RENDER_ERROR__`，阻断下游编码产出无效视频。

## 3. 画幅、安全区与参数化布局 (Stage Geometry & Safe Areas)

Rhine Renderer 采用完全独立的 1920x1080 响应式阶段图层，全面废除旧 Pen 模板的硬编码死尺寸（如 `YS=[187, 401...]`、`LEFT=['DLOWp'...]`）：

```
0,0 ───────────────────────────────────────────────────────────── 1920,0
│                                                                     │
│   40,36 ┌───────────────────────────────────────────────┐ 1880,36   │
│         │ Top Header: 72,40 (w:1776, h:74)              │           │
│         │ [RHINE LAB ACCESS]        [STATUS] [PROGRESS] │           │
│         ├───────────────────────────────────────────────┤           │
│         │                                               │           │
│         │ Stage Content Area: 60,124 (w:1800, h:856)    │           │
│         │ (Hero Panel / Specimen + Telemetry Matrix)    │           │
│         │                                               │           │
│         ├───────────────────────────────────────────────┤           │
│         │ Bottom Footer: 72,990 (w:1776, h:44)          │           │
│         │ [FRAME/BEAT]                       [24.0 FPS] │           │
│   40,1044 └─────────────────────────────────────────────┘ 1880,1044 │
│                                                                     │
0,1080 ───────────────────────────────────────────────────────── 1920,1080
```

### 参数化计算契约：
- **画布基准**：`1920 x 1080`，严格 `24.0 FPS`。
- **安全外框 (Safe Area)**：`x: 40, y: 36, width: 1840, height: 1008`。
- **顶部遥测 (Header)**：包含归档标题、协议编号、密级遥测以及全时序连续进度条（Progress Ribbon）。
- **底部遥测 (Footer)**：包含当前帧号、总帧数、拍点（Beat）及相机宏观/微观坐标。
- **动态玩家槽位布局 (`computePlayerSlotLayout`)**：
  - 支持任意玩家数量 $N \in [1, 8]$。
  - 水平模式槽宽：`slotW = (availableW - (N - 1) * gap) / N`。
  - 垂直矩阵槽高：`slotH = (availableH - (N - 1) * gap) / N`。
  - 自动适应 5 玩家、8 玩家或单玩家展示，不发生重叠或越界。

## 4. 连续运动感与转场时序 (Continuous Motion System)

为了打破“1秒切1人”造成的幻灯片硬切（PPT 感），Rhine 引入连续时序动势系统：

| 时序阶段 | 帧范围 (单干员24帧) | 动势特性 | 视觉表现 |
|---|---|---|---|
| **切入阶段 (Enter)** | 0 ~ 4 帧 (0.00 ~ 0.20s) | 三次方缓出减速 (`1 - (1-p)^3`) | 面板从右侧 +38px 平滑减速切入，透明度由 0.6 升至 1.0；高科技垂直扫描线扫过。 |
| **稳态展示 (Steady)** | 5 ~ 19 帧 (0.20 ~ 0.82s) | 呼吸感微动 (`sin(beat * π)`) | 面板坐标归零锁定，相机微呼吸（Zoom 1.0 ~ 1.01），数据流平稳脉动。 |
| **切出递进 (Exit)** | 20 ~ 23 帧 (0.82 ~ 1.00s) | 二次方前向递进 (`p^2`) | 面板产生 -20px 前向加速度与 0.2 透明度衰减，顺滑交接给下一个入场干员。 |

### 跨场景背景连续性 (Cross-Scene Continuity)：
- **网格视差**：全局垂直网格以 `(frame * 1.2) % 160` 连续水平横移，不随干员切换而重置。
- **扫描波**：全局能量脉冲波以 `(frame * 0.045) % 12` 周期平滑横跨全屏。
- **索引推进**：顶部进度条根据 `frame / total_frames` 连续推进，指示整个报菜名进程的平稳演进。
